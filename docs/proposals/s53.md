# s53 — Placemaker anarchy, stall marking size, build audit

Playtest (screens 84-86): lots and malls built as bare asphalt: "left out 391 rejected parts (OverlapExisting x356 [ParkingLotDecal01 x339 ...])",
"parking: 9 of 400 stall markings built". `ParkingLotDecal01` has a 3.2 x 6.2 m collision box on 3.0 x 5.9 m stalls, so every neighbour pair collides.
Since 2b97af4 the markings are no longer sunk, so the game's OverlapExisting reached the retry loop, which left them out.

## Placemaker anarchy (setting "Ignore collisions in my builds", default on)

* The game's apply gate is `ToolBaseSystem.GetAllowApply` (no Error entities unless `ToolSystem.ignoreErrors`); `ApplyObjects/Nets/AreasSystem` never read
  `Error`. Our `BuildToolSystem` requests Apply itself, so the only gate is `BuildService.DoValidate`.
* `ClassifyOwnCollisions` (Game/Build/BuildService.Audit.cs): an error is ignored only when it is OverlapExisting / NotEnoughClearance (from the notification icon
  of that temporary; several types on one piece = real), on an OBJECT of the plan, the object overlaps another planned object (Core/Build/OwnOverlap, Declutter
  footprints) and it touches no existing building (captured `Plan.Protected` + live Building lots/footprints around the plan). Nets, areas, surfaces and
  everything touching the city keep the old path (exclude and retry; SiteSafety / ProtectBuildings unchanged).
* When every remaining error is ignorable the build proceeds to Apply; otherwise the retry loop runs but skips the ignored errors (no piece is left out for them).
* Ghost: an object that overlaps another planned one is emitted non-optional (an optional one was cancelled together with its neighbour, and the instant build
  adopted the ghost as it was).
* Log: `Placemaker anarchy: cleared N self-overlap error(s).`

## Stall marking size

`Core/Layers/Parking/ParkingMarkings.Scale`: the regular/electric marking (3.2 x 6.2) is scaled to its stall minus 3 cm, never below 0.85 (3.0 x 5.9 stalls: 0.928).
Accessible markings (5.0 wide) stay 1. Needs an in-game look: does the parking lane (owned by the decal) still connect and cars park?

## Build audit

* Log block after every build: `build audit: planned N, built M, left out K` + by kind + one line per reason with top prefabs.
  Reasons: `rejected:<ErrorType>`, `anarchy` (kept, not counted as left out), `site-safety`, `declutter` (plan-time, from the plan's Declutter issues),
  `asset-missing`, `zoning`. (`budget` / `no-fit` exist as ids; nothing emits them yet.) Terraform and paint are never left out one by one.
* `ModsData/Placemaker/audit/group-<id>-<time>.json`: every entry (kind, prefab, reason, x, y, z, count).
* Panel: after Build the Area stage shows a "Left out: N" chip (`summary.audit`); click lists reasons with counts, hover marks where those pieces
  would have been (amber circles; `hoverAudit` trigger, overlay DrawErrors). Cleared with the next change like the other build notes.

### Zoning per plot

After the zoning check (`VerifyZoning`) one line per plot (original cutout quad): cells the Design preview showed (snapshot at build start),
cells planned after the re-snap, cells the game really has zoned (live ZoneBlock cell state 4), buildings standing on it:
`zoning plot 3 at (x, z) Commercial...: preview 4, planned 4, live zoned 0, buildings 0  <-- differs`. A plot with preview cells not live-zoned becomes a
`zoning` audit entry ("Shown in preview, not zoned"). Buildings are counted at build time, so a zoned plot that has not grown yet shows `buildings 0`
with live = planned = preview: that is "zoned, not grown", not a mismatch. Screen 87 (plaza: 4 notches grew shops, 4 are lawn): the next playtest log tells
which of the two it is; no preview change was made without that evidence.
