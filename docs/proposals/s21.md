# s21 — decal overhaul (decals complement every feature, take no space)

Full write-up, census and rules: `docs/DECALS.md`. This file lists what touched shared/lead-owned code and why.

## New (owned by s21)

- `Core/Decals/DecalCatalog.cs` — what a decal is (family, shape, ground, natural orientation, functional), from the
  item part of the prefab name and the real footprint.
- `Core/Decals/DecalPools.cs` — 16 dressing pools (`decal.oil`, `decal.tyre`, `decal.leaves.edge`, `decal.mulch`, …) with
  size caps/minimums and fallbacks; `DecalDressingRules : ICategoryRules, IVarietyCategories` (reflection plug-in) adds
  them during classification and owns their automatic eligibility.
- `Core/Decals/DecalFit.cs` — after automatic resolution, turns long-X prefabs 90° so the long axis follows the planned
  yaw.
- `Core/Decals/DressingProfiles.cs` — `DressSettings`, per-type profiles (families + default style + preset styles),
  the shared controls (`dressAmount`, `dressStyle`, `dress<Family>`).
- `Core/Decals/Dressing.cs`, `DressingRules.cs`, `DressingWorld.cs` — the complement pass.
- `Lang/en-US.dress.json`, `Tests/Placemaker.Tests/DecalsTests.cs`, `DecalsCensusTests.cs`, `docs/DECALS.md`.

## Contract / shared edits (small, please review)

| file | change | why |
|---|---|---|
| `Core/Composition.cs` (lead) | `Compose` keeps a plan → `DressSettings` map (`Run` gained two optional params) and calls `Decals.Dressing.Apply` after `PathJoins.JoinAll`, before `Cutouts.Enforce` / `SiteSafety.Apply` | dressing must see the whole composed plan; cutouts and lot safety must apply to decals |
| `Core/Layers/Common/LayerBase.cs` | ctor appends the dressing controls for fill layers with a profile (`AddDressingControls`); `Preset()` stamps the preset's decal style | one consistent place for every type without touching each layer |
| `Core/Layers/Parking/ParkingLayer.cs` | same controls + preset style (it is not a LayerBase) | |
| `Core/Build/Declutter.cs` | `Tier(Decal) = −1` (does not participate) | decals take no space; no "didn't fit" |
| `Core/Layers/Common/ObjectBudget.cs` | decals neither count toward the cap nor get thinned | own budget in the dressing pass |
| `Core/Build/AssetCuration.cs` | `MaxFootprint` / `FitsSize` consult `DecalPools` caps and minimums | pools that fit their hosts (no 30 m stains, no 0.3 m tyre bits) |
| `Core/Build/SiteSafety.cs` | decals dropped on lots are not counted in "left out" | dressing, not planned content |
| `Core/Layers/AddOns/DecalsAddOn.cs` | no occupancy checks, no `NoGround` issue; falls back to any dry ground; never on water | "there is never not room for decals" |
| `Game/Build/BuildService.Emit.cs` | decals emitted with `m_Elevation = −0.01` (`SinkDecals`, setting "Decals never collide") | `GetCollisionMask` → Underground only: no collision with ground props/trees/nets in ghost, build and OverrideSystem |
| `Game/Assets/AssetCatalogSystem.cs` | `DecalFit.Orient` before Declutter in `ResolveAutomatic` | orientation by resolved prefab |
| `Game/Settings/PlacemakerSettings.cs`, `Lang/en-US.tool.json` | `DecalsNeverCollide` (default on) | escape hatch if sunk decals do not render |
| `Tests/Placemaker.Gallery` | `DecalFit` after resolve, decals in category colours + legend (pixel font in `Raster.cs`), `--decals` variants (max / gritty / off) | visual check |
| `docs/ASSET-CURATION.md`, `Tests/.../Fixtures/catalog-bounds.json` | regenerated (`PM_WRITE_CURATION=1`): new pools | gallery uses the real pools |

Proposed for the lead: `PlannedObject` could carry an explicit "align long axis" flag instead of the convention
"decorative decal yaw = long axis" (DecalFit); and `AssetTraits` is out of bits (decal layer mask as a trait would let
pools exclude terrain-only decals from path dressing) — consider widening it to `long`.

## Needs in-game verification

1. Sunk decals (Elevation −0.01) render in the normal view (they move to the Tunnel mesh layer). If not: turn the setting
   off, then look for another non-colliding emission (e.g. owner-grouped decals).
2. Paths are drawn on the Roads decal layer; pack decals with mask 1 (terrain only) will not show on paths.
3. Decal counts at 100 % (≈ 120–330 per 1.2 ha in the gallery) feel right in game and build fast enough.

## Test expectations changed (intentionally)

- Control-count / section-count limits in the type tests (`Assert.InRange(...Controls...)`, kits `TypeWaveKit06`,
  `FarmTypeTestBase`, `T04TypeTestBase`) now exclude the shared dressing controls (`DressingControls.IsDressingId`),
  like Fairground already excluded the street-shop options.
- "Objects clear of paths" (`TestKit.AssertObjectsClearOfNets`) and "feature objects stay in their place / host objects
  stay out" (Fields, Monuments, ParkPlazaDepth) skip decals: decals may lie on paths and straddle outlines by design
  (LeisureTests and the plaza amenity test already did).
- `BuildDeclutterTests.PriorityKeepsCenterpiecesAndFurnitureOverDecals`: the decal now stays, with no issue.
- Sports park field-line test and golf "no decals" test look at functional decals only; parking schema order test
  ignores the dressing controls; parking English-text test also reads `en-US.dress.json`.
