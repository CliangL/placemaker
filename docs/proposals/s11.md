# s11 — "Block paint" selection mode (fill-aware brush)

User request (playtest): block mode is the favourite, "like the paint bucket"; make it smarter — draw a
shape that never crosses roads, only paints in the area it is in, and knows to avoid zoning.

## What the mode does

- **Mouse-down** picks the city block under the cursor with the same face tracing as Block mode
  (`RoadNetwork.PickBlock` → `PlanarGraph.PickFace`, curb outline from `RoadNetwork.BuildArea`).
- The stroke paints with the normal brush (size / round / square / angle from the Brush section, shared
  with Paint), but every stamp is **fenced** to that block: `BrushMask.Limit` = the block's paintable
  cells, so drifting over the road paints nothing there.
- **Obstacles** (never painted, shown in a faint red tint while selecting):
  building lots, lot-type areas (other Placemaker areas, parks, extractor lots…), **zoned cells**
  (`Zones.Cell.m_Zone != None`, visible, not blocked), water deeper than 0.3 m. Option
  *"Block paint: keep off empty zone cells"* (Options → General, default off) also avoids the visible
  empty zone grid. Members of the group being edited are not obstacles.
- **Erase**: right-drag (as Paint) or Shift+drag. Shift + mouse move turns a square brush (as Paint).
- **Another block**: a paint stroke that starts in a different block starts a new selection there
  (the previous block is one Ctrl+Z away). Rationale: two blocks are always separated by a road, so the
  union can never be one outline; silently refusing would feel broken. Erase strokes never switch.
- **Outline** (`Core/Geometry/BlockBrush.Outline`): lightly smoothed brush outline (1 smoothing pass
  instead of Paint's 6 — Paint shrinks a 30 m stroke by a third), then a morphological closing of
  (paint ∪ forbidden) pulls every edge within 6 m (1.5 cells) of the curb or an obstacle exactly onto
  it, then exact clip to (block − obstacles), largest piece kept. Unpainted gaps are filled (as Paint);
  an obstacle enclosed by paint is opened with a 1 m corridor (CS2 areas have no holes). Edges on the
  curb are exactly on the curb line, so attachments / entrances still see the road. Source = `Painted`
  (frontage partly road, partly not — `Block` would tell Roads the whole outline is road).
- **Overlay**: current block = faint dashed curb line; obstacles = faint red fill; the block a new
  stroke would start in = dashed white; painted cells while painting, the final outline otherwise;
  brush cursor red while erasing.
- **Hints**: panel/tooltip hint lines per state (start / paint / erase / shaded = won't paint / another
  block starts over), like the other modes. Vanilla apply-action relabelling stays Draw-only, as for
  Block and Paint.

## Verified by unit tests only (`Tests/Placemaker.Tests/GeometryBlockBrushTests.cs`)

Fence (stamps over the road paint nothing, erase unfenced), curb hugging (edge exactly on the curb over
the painted width), small gaps to the curb closed, free edges keep the brush size, zoned strip avoided with
the cut exactly on the zone line, enclosed building cut out without a hole, painted gaps filled, lot that
splits the block → largest piece, narrow unpainted strips elsewhere not swept in, water predicate, fully
blocked block, bad input, 24-sided block with ~150 zone obstacles (simple, inside, fast), Trim, mode id
round trip, face comparison. Results are simple CCW and pass `SurfaceAcceptance.IsAccepted`.

   `Visible`, not `Blocked`, and `m_Zone.m_Index != 0`. **Unsure**: whether every zoned cell along a road
   is `Visible` (the grid of a block behind another block can be `Shared`/`Redundant`), and whether cells
   under a Placemaker area become `Blocked` (they should, then they are skipped and the lot covers it).
   Cell geometry from `ZoneUtils.GetCellPosition` (y grows away from the road, against `m_Direction`) —
   check the red shading lines up with the zone grid.
2. That zone cells start at the same line as the curb outline from `EdgeGeometry` (sidewalk edge); if
   there is a gap, a thin unpainted strip would stay along zoned frontage (harmless, but visible).

4. Lot areas: `Areas.Lot` from the area search tree — Placemaker's own owner lots must show as obstacles;
   when editing a group (Edit → switch to Block paint) its own lot must not.
5. Feel: snapping distance 6 m (1.5 brush cells) — enough to "reach the road" without grabbing curb
   strips the player meant to leave free? Fillets of ~3 m radius where a stroke meets the curb.
6. Performance on big irregular blocks (unit test: ~150 obstacles, < 3 s worst case on CI, typically
   tens of ms; re-outline is throttled to 0.15 s while painting like Paint).
7. Keep-off-roads (AreaClip) still runs on the result (source `Painted`); it should only see slivers

8. Five mode buttons in one row: "Block paint" label width at the default panel width (mock tests pass).
9. UI build note: `npm run build` writes to the game Mods folder when `CSII_USERDATAPATH` is set

## Follow-up 1 — open-land fallback

No closed block under the stroke start (open land, a dead-end road, an unfinished grid, a ring that
doesn't close, or a face too large to trace): Block paint no longer refuses. It builds a 600 m work box
around the stroke start (`BlockBrush.Open`). The obstacles are the same as before plus the **road
footprints** (`AreaClip.Corridors` with no extra margin: the centre curve ± half the composition width,
which in CS2 includes the sidewalks, with round caps over the nodes). The fence is the
**4-connected component of paintable cells containing the stroke start**
(`BrushMask.ConnectedComponent`), so a stroke dragged across a road never paints the far side, while
a dead-end road can be painted around. A stroke that starts outside that component starts a new
selection, as a new block does. The outline is the same pipeline (one ring, 6 m snap onto the road
edges and obstacles). Overlay: no dashed block line; roads and obstacles are shaded only near the brush
(within brush radius + 60 m, re-filtered every 16 m of cursor movement). Undo state:
`BlockPaintState.Open/Seed`. Limit: in open land the brush cannot reach more than 300 m from where
the selection started.

## Follow-up 2 — Brush rules (everything about the brush is customizable)

`Core/Geometry/BrushRules.cs`: one toggle per obstacle kind: Roads, Buildings, Lots/areas, Zoned
cells, Empty zone cells, Water (defaults: all on except empty zone cells). Also Stay in one block
(default on), Snap 0–20 m (0 = off, default 6) and Smoothing 0–6 passes (default 1; Paint uses 6).
`BrushRules.Build` picks the brush:
- Lock on and a closed block under the start: fenced to that block.
- Otherwise: the open box, kept on the start's side of the roads only when Roads is on.
- Nothing left to stop at: `BlockBrush.Free`, which is **plain Paint**: no fence, Paint's outline
  pipeline with the Smoothing slider. With smoothing 6 the output is identical to Paint, and a unit
  test checks this cell for cell and vertex for vertex.

The Paint mode itself is unchanged and never reads the rules.

- Settings (persisted, Options → "Block paint brush" group): `BrushStopRoads`, `BrushStopBuildings`,
  `BrushStopLots`, `BrushStopZoned`, `BlockPaintAvoidEmptyZones` (id kept from s11), `BrushStopWater`,
  `BrushStayInBlock`, `BrushSnapDistance`, `BrushSmoothing`, plus a `ResetBrushRules` button.
- Panel (Block paint only): a collapsible "Rules" row under Brush. It has 7 icon toggles (roads,
  buildings, areas, zoned, empty zones [new icon], water, one block [lock]), Snap and Smooth sliders,
  and a reset icon button. Each control has a one-sentence tooltip.
- Contract (additive): `BrushRules` interface; `ToolState.brush.rules?`; triggers
  `setBrushRules(json: Partial<BrushRules>)` and `resetBrushRules()`. C# side:
  `UiModels.BrushRulesJson/ParseBrushRules`.
- Obstacles are now gathered tagged by kind (`BrushObstacle`), and empty zone cells are always
  gathered so the rules can pick.
- Changing rules re-fences on the next stroke and rebuilds the outline. It is a setting, so it is not
  an undo step. A block chosen while the lock was on stays a block until the next new selection.
- Tests: each obstacle toggle on/off (painted vs not, in or out of the outline), defaults, water, roads
  in open land, lock on/off, snap 0 vs 6, smoothing, all-off equals Paint, panel JSON merge/clamp.
