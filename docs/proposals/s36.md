# s36 — the game's depth rule, and cutouts that keep it

Playtest (17:31, images 67/68): park on Bellflower Street (4-lane, curved). Design showed one column of 2 cells in the
left plot (≈ 2 × 4 cells), none in the right one; after the build none at all. Log: `zoned 0 of 2 cutout cell(s) …
blocked 2`, cause `row 0 with row 1 blocked x1, behind a blocked cell (row 0) x1` — circular, no direct source.

## The game rule (decompiled 1.6.2f1, `Game.Zones.CellOverlapJobs`, the `CellFlags.Blocked` pass)

After `CellBlockJobs` (nets with BlockZone, physical lots; `CleanBlockedCells`: row 0 blocked when row 1 is, every
cell behind a blocked cell blocked), each block evens out its **column depths** (`depth(x)` = first blocked row,
neighbour blocks of the same road continue the row via `GetDepth` past the block's ends):

```
walk a = 0 → n−1 and b = n−1 → 0 at the same time:
  ReduceDepth(a, CalculateLeftDepth(a));  ReduceDepth(b, CalculateRightDepth(b))
CalculateLeftDepth(x):  d0 = depth(x−1), d2 = depth(x)
  if d2 <= d0                       → d2
  if d0 != depth(x−2) and d0 != 0   → d0
  d4 = depth(x+1)
  if d4 − d2 < d2 − d0              → min(max(d0, d4), d2)
  if depth(x+2) != d4               → min(max(d0, d4), d2)
  else                              → d0
(CalculateRightDepth mirrored.)  ReduceDepth(x, k) blocks the column from row k on.
```

Consequence: a column deeper than both neighbours is cut to the deeper neighbour unless a neighbour of its own depth
stands beside it. **A lone 1-column cutout (depth 2 between blocked columns of depth 0) is blocked entirely** — exactly
the playtest: the curved road's cells sat at an angle to the plot drawn along the outline, the centre rule gave the
plot one column, the game then blocked it (rows 0 and 1 → "row 0 with row 1 blocked / behind a blocked cell").
A 2-column cutout of equal depth survives.

## Fix

Core `Build/ZoneGuard.cs`:
* `ReduceDepths(grids, depths)` = port of the rule (both walks, neighbour blocks found geometrically).
* `GameDepthPass` (after the cell selection): the depth the game will see per column = first row closed (road,
  hidden, our nets) or under a blocker (inside the footprint inset and not covered by any zoned cell of any block,
  grown by the blocker margin — overlapping blocks' zoned cells are holes in the blocker); zoned columns the rule cuts
  keep the rows above the cut, or go when < 2 rows remain; repeated until stable. Preview == game.
* **Widen lone columns**: a plot left with a single column takes the neighbour column whose cells lie ≥ 20 % on the
  plot (open, not another plot's, not taken) — the curved road's 2-cell plot gets both columns.
* Live check (`BuildService.VerifyZoning`): the cause of a blocked cell is now looked for in the cell and every cell in
  front of it (blocker lot / our net / physical lot); otherwise it reports the depth rule with the neighbour depths.

## Tests

`ZoneGuardDepthRuleTests`: the rule (lone column → 0; two columns survive; a single deeper column cut to its
neighbours); a curved 4-lane road (24 m, R 160) with a 2 × 4-cell plot drawn along the outline → ≥ 8 cells, and under
the game's rules (blockers, CleanBlockedCells, depth rule) every planned cell survives; a lone column is widened or
dropped, never left for the game to block. Updated: `ZoneGuardLaneTests.The_builds_own_paths…` (a column left alone
beside a path is now correctly not planned).

## Known: commercial layouts that cannot be zoned (not fixed here)

With the rule modelled, some Mall district / Retail park plots are honestly unzonable and ZoneGuard drops them with
`Placemaker.Issue.CutoutNotZonable` (CommercialS32 / Commercial tests: mallDistrict sq25/sq40/big, retailPark trade L).
Cause: plots 12 m wide either side of a 3 m paseo walk; the walk closes the cell column it crosses, each plot keeps one
column, the game blocks it. Needs the planners to snap rows to the lane's cell grid (whole cell columns, a free column
for each walk) — attempted (Mall finish-time snapping, longer minimum stretches, merged collinear lane prediction) but
each changed many other layouts; left for a planner pass.
