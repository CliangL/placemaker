# s42 — Design as "pick what to make", compact Review, four Area tools

Playtest asks (lead, from mockups the user iterated on): the Design stage should read top to bottom as *pick → what am I
editing → how it's built → optional add-ons*, dense and aligned like an engineering program, with a fun coloured icon on
every category, type, style and extra. Review and Area: "way too much text bloat; alerts roll off and do the
dot-dot-dot thing; the breakdown is unreadable; bake the 'I understand' next to Build". Area: four tools with plain names.

No contract change (PROTOCOL stays 21). One small Game change (keep-off, below) and the missing generator groups.

## Design stage (`UI/src/stages/DesignStage.tsx`, `PresetBrowser.tsx`, `Controls.tsx`)

1. **Picker panel** — one bordered panel, header "PICK WHAT TO MAKE" (folds; search icon on the right), three rows with a
   numbered label (`1 Category`, `2 Type`, `3 Style`), hairline dividers, no indentation. Each row wraps 24rem chips:
   coloured icon tile + name + small count (categories: types; types: styles). Selected = blue outline/fill.
   * Categories come from the type's `GeneratorRegistry` group (`RecipeInfo.group`); the id guess is only a fallback.
     The most used 7 are shown (local use count, snapshot at mount so chips never jump while clicking; default order
     Parks, Squares, Roads, Shops, Parking, Gardens, Water, …), the rest behind "N more". The current category and the
     selected type's category are always visible. "All" is gone (search covers it).
   * Styles = the engine's presets: Default, built-ins (amber dot = saved over), the player's own (gold star tile),
     then a dashed "+ New" (save the current settings as a new style). The active style shows a blue dot when modified.
   * Search (header icon) filters all three rows: categories with hits, matching types of every category, matching
     styles of every type (Enter picks the first hit, Esc closes, arrows walk the chips).
2. **Editing bar** — "EDITING" strip + "● unsaved changes"; breadcrumb chips `[Category] › [Type] › [Style]` (style
   highlighted); icon toolbar: undo changes (re-applies the style), shuffle (randomize), + (save as new), save (overwrite;
   primary blue, disabled with the reason: "Default can't be changed. Save as a new style." / "No changes to save"),
   ⋯ (rename, delete, reset to shipped, export). Replaces the old Save / Save as… text bar and the repeated type header.
3. **Entrances** — one framed line: icon · Entrances · "Add one to build" (amber) or the count · typed buttons
   (2-way / In / Out / Alley / Path); placed ones as small chips under it (show / remove). Footer "Add an entrance to
   build" still leads here (scroll + flash). No fold any more.
4. **Shape — how it's built** — the type's control groups as one-line heads in **two columns** (chevron · name ·
   summary right-aligned). Heads never move: an open section unfolds full width *under its pair* (blue left rule;
   a small title when both of a pair are open). All sections start folded (remembered per type). Inside, sliders and
   switches pair up only when their label is short (≤ 13 characters), so labels are never cut.
5. **Extras — optional add-ons** — the type's features as one-line rows in two columns: chevron (when it has options)
   · coloured tile · name · fit tag or summary · switch. Fit is inline on the extra: "9/16 fit" (from
   `Placemaker.UI.Feature.SomeMissing` args) / "Reduced" amber, "No room" red; the heading keeps a "2 didn't fit"
   total. The first 8 (and every enabled one) are listed, the rest behind "N more". Disabled-with-reason (s15) unchanged.

Kept: linked controls, disabled-with-reason, availability, road mix / palette cards inside their sections, legend window,
custom presets (save, save as, override, rename, delete, reset, export), keyboard walk of the chips.

### Icons and colours (`UI/src/lib/palette.ts`, 61 new SVGs in `UI/src/assets/icons`)

Category palette (tile colour, inherited by types and styles): roads cyan, parks green, gardens pink, squares sand,
sports orange, water blue, nature teal, farms wheat, events purple, industrial steel, transport periwinkle, parking blue,
shops raspberry. Every shipped type has its own glyph (beach umbrella, waterfront boat, quarry pickaxe, fairground
wheel, zen garden stones…). Styles pick a glyph by keyword in their id/name (forest → tree, harbour → waves, formal →
crown, market → awning…) with the type glyph as fallback. Extras have their own role colours (water blue, play orange,
planting green, ground brown, monuments purple, amenities raspberry). Glyphs render dark on the tile (baked "dark" tint).

## Review (`ReviewStage.tsx`, `ParkStatsSection.tsx`, `Panel.tsx` footer)

1. Money card: `COST ¢x  UPKEEP ¢y/month … 5.29 ha` on one line; one stacked bar of the cost by friendly bucket (the type
   itself in its category colour, then Water / Planting / Ground / Play / Amenities / Zoning / Extras, ≤ 5 + Other) with a
   one-line legend "Park 75%"; the per-step list is the bar's tooltip and unfolds on click.
2. Stat chips: icon + bold number + one word (optional `<stat>.Short` key).
3. Alerts as chips (2–3 words, never cut): permanent changes and warnings amber, errors red, info blue; full sentence in
   the tooltip; click shows it on the map or edits the step; "+N more". Short labels: `<key>.Short` in the new
   `Lang/en-US.short.json` (218 keys: every `.Issue.` / `Placemaker.Permanent.` key and the two fit keys); without one,
   the first clause cut to whole words, never ending on a filler word.
4. Park stats: one row of five mini tiles (Tourism, Leisure, Reach, Capacity, Wellbeing: value + tiny bar with the
   vanilla band); "Edit" unfolds the sliders (meanings moved into tooltips).
5. Footer: `[☐ OK, permanent]` chip beside the Build button when permanent changes need the tick; a blocked button's
   label *is* the blocker ("Add an entrance to build", "Tick OK to build", "Not enough money"); no separate reason row.

## Area (`AreaStage.tsx`, `area.module.scss`)

Four equal cards (tile + name + one short line): **Points** "Click corners" (draw), **Paint bucket** "Click to fill"
(block), **Paint area** "Brush it on" (paint + block paint), **Road nodes** "Click road corners" (perimeter). Paint area
has **Smart edges** (switch, default on): on = block paint (`setAreaMode("blockPaint")`, `anything:false`), off = plain
paint over anything (`setAreaMode("paint")`, `anything:true`). Under it, always visible: stop chips (Roads, Buildings,
My builds, Lots, Zoned, Empty zones, Water), One block, Snap, Smooth (greyed while Smart edges is off), then Shape and
Size; Angle only for the square brush. Points / Paint bucket / Road nodes: "Keep off" chips (My builds, Clip to free
land). One summary line: Area · Edge · Corners · "drag corners anytime" · Clear. Mode ids and saved settings are
unchanged; a saved Block paint opens Paint area with Smart edges on. Mode names, tooltips, hints and settings texts in
`Lang/en-US.tool.json` follow the new names and were shortened.

**Game change** (`Game/Tool/PlacemakerToolSystem.KeepOff.cs`): "Paint over anything" no longer switches the outline
tools' keep-off off — it is now Paint area's Smart edges switch, so the Points / bucket / nodes chips stay independent.

## Open points

* Paint bucket "Keep off: Zoned" from the mockup is not a real option today (block outlines honour My builds and Clip to
  free land, which includes zoning) — shown as those two chips.
* Points "Snap to" chips: Draw has no snap toggles today (it always snaps to curbs / right angles), so none are shown.
* Short labels for other locales: only en-US has `.Short` keys; other languages fall back to the clause rule.
* Style glyphs by keyword are a heuristic; presets could carry their own glyph later (`PresetView.icon` exists but holds game icon paths today).
