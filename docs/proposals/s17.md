# s17 — park stats (attractiveness, leisure, coverage, upkeep) as the last thing to configure

Research and formulas: `docs/PARK-STATS.md`. All contract changes are additive.

## Contract changes (lead, please review)

Core
- `Core/Composition.cs` `Recipe.ParkStats` (`Build.ParkStatsSettings`, null = suggested values); `Recipe.Clone` copies it.
  Not in recipe JSON, presets or the "modified" fingerprint: it is per build.
- New `Core/Build/ParkStats.cs`: `ParkStatIds` (save-format ids: attractiveness, leisure, coverageRange,
  coverageCapacity, entertainment, upkeep; `attractiveness.inGame` for the value set on the lot), `ParkStatsKind`,
  `ParkStatsSettings` {KeepVanilla = true, Overrides}, `ParkStatsRecord`, `ParkStatsInput.From(plan, areaM2, recipe)`,
  `ParkStatsEstimator.Estimate/Band/Comparables`, `ParkStatsResult`.
- New `Core/Build/VanillaParks.cs`: 52 vanilla park prefabs with their real component values.
- `GroupRecord.ParkStats` + `ReceiptCodec` **v2**: one length-framed block appended after the area block
  (keepVanilla, overrides, applied values, kind, leisure type). Decode puts the settings back on `Recipe.ParkStats`
  so Edit keeps them. v1 receipts decode unchanged; v1 readers ignore the extra block.
- `PROTOCOL` / `UiModels.Protocol` bumped to 17 (master: 16) (new summary field + triggers).
- `UiModels.SummaryInput.AreaM2`; `UiModels.Summary` adds `parkStats` when the recipe is a park type;
  `UiModels.ParkStats(result)`.

UI (`contract.ts`)
- `Summary.parkStats?: ParkStatsView` (`ParkStatView`, `ParkStatId`).
- Triggers `setParkStat(id, valueJson)`, `resetParkStat(id | "")`, `setParkStatsKeepVanilla(bool)`.
  Undoable, never re-plan (they bump only the design version and `ParkStatsVersion`).

Game
- `BuildService.FinishParkStats` (FinishRecord): stats into the receipt, "Attractiveness" into the record stats, vanilla
  `AttractivenessProvider` on the owner lot (× terrain bonus). Setting `ApplyParkStats` (default on).
- `GroupRegistrySystem.SyncParkStats` after load (restore / remove per setting).
- `ToolRegistration.SettingsLocale` now also maps the build options that had Lang keys but no mapping
  (ClearExistingTreesAndProps, RecoverRejectedPieces, OverlayPavedSurfaces, ChargeNetConstruction, SelectAsOneThing,
  ConfirmBulldoze) — they showed raw property names in Options.

## UX

Review gets a "Park stats" fold (open by default, after issues and breakdown, before the permanent-effects box): a
"Keep within vanilla range" check, then one card per stat — label, "In game" / "Shown only" tag, value, one-line
meaning, slider (vanilla range while kept, hard limits otherwise), reset, and a "How it's calculated" fold with the
formula lines and "Similar to: Winding Park (0.9 ha) 20 · …". A gentle warning appears when values are outside the
vanilla range. Not shown for parking, roads and industrial types. Mock: the host returns `parkStats` from the real
Core; `mock/tests/parkstats.spec.ts` covers suggest → override → clamp → range off → reset.
