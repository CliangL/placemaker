# s59 — "it says parts overlap": why builds were refused, and the fix

User, 2026-10-15: *"Nine times out of ten I can't place anything anymore — it says parts overlap. I don't care if things overlap, just
place them."* Then: *"Don't let the game reject them. Turn on anarchy and just build what we want to build."*

## Plain answers

**What is the fundamental problem?** The game checks every piece we place as if a player had plopped it by hand, on its own, and
our build code then treated the game's complaints as orders. The game never needed those complaints to place things — *we* refused.

* Every piece a Placemaker build emits (stall marking, bush, leaves decal, lamp, path) becomes a separate, top-level, *Essential*
  temporary: `GenerateObjectsSystem` sets `TempFlags.Essential` on every object made from a `CreationDefinition`.
* `Game.Objects.ValidationHelpers.ValidateObject` checks each temporary against every other temporary (`objectList`, `edgeList`)
  and against the city (object/net quad trees). Two pieces are only exempt from each other when they share a **top-level owner**
  (the `Owner` chain, `entity3 == entity9` / `m_TopLevelEntity == entity`). Ours have no owner at that stage (the s55/s58 carrier
  owner is given *after* Apply), so stall marking vs stall marking, bush vs bush, marking vs our own lot lane, decal vs decal are
  all flagged. Because the pieces are Essential, the soft outcomes (`Override` = hide the loser, `Warning`) never apply: every
  touching pair is `ErrorSeverity.Error`, and the game puts the `Error` on **both** pieces but the icon on only one.
* **Apply ignores `Error`.** `ToolApplySystem` turns `Warning` into `Deleted` and `Override` into `Overridden`;
  `ApplyObjects/Nets/AreasSystem` skip temporaries with `TempFlags.Cancel`. Nothing else is looked at. Vanilla tools refuse to
  apply because `ToolBaseSystem.GetAllowApply` checks for `Error` (that is the switch the Anarchy mod flips) — our own
  `BuildToolSystem` never asked it. It was our `DoValidate` that read the errors, left the flagged pieces out, re-emitted the whole
  build and validated again — up to 6 times — and then gave up with "parts overlap".

**Was nothing overlapping before?** Things always overlapped; the game always flagged them. What changed is how many, and what we
did with the flags:

| when | change | effect |
|---|---|---|
| 10-13 `f7fa1c1`/`378b624` | exclude-and-retry loop (4 → 6 attempts) from the first game layer | a flagged piece is removed and the build re-emitted |
| 10-13 `ee16b30` | ghost objects `Optional`, instant build from the ghost | the game's `CancelOptional` silently cancelled colliding pairs — builds "worked", pieces vanished (FEEDBACK-4: 480 of 553 dropped) |
| 10-14 `eb0f1f3` (s25) | stall markings/chargers/arrows never optional, never excluded; lots get graded terrain | the first pieces the loop could not remove → refusals start ("60 parts overlap", playtest 77). Terraform also means lots no longer take the instant (optional) ghost path |
| 10-14 `c693be6` (s44) | markings sunk so they don't collide | reverted (`2b97af4`): the game rejected sunk markings |
| s50 `7c884ae` + dressing | lot-first islands, edges, leaves/stain decals | many more pieces per build → many more pairs |
| s53 `5a7e7e3` | "anarchy": ignore an error only if the piece overlaps *another planned object* | the partner of each pair (Error, no icon) and pieces against nets stayed "real" → still refused |
| `ff46338` (lead stop-gap) | ignore any error on our objects unless it touches a building | nets, partners without a plan match and non-overlap types still went through the loop |

So "it was working a while ago" = the loop and the optional ghost *deleted* the colliding pieces and built the rest (holes like
the empty patch circled in screenshot 97). Since s25 the loop met pieces it may not delete, and since s50/dressing there are far
more pairs — it ran out of attempts.

**Was anarchy working better before?** No — it never removed the cause. s53 only stopped *counting* some errors; everything else
still went into the retry loop.

**Is a loop that tries six times stupid?** Yes. Each round removes some pieces, re-emits ~150–700 temporaries and validates
again; the counts in the log shrink (183 → 126 → 120 → 84 → 56 → 42 → 33) but never reach 0, so the build fails after 6 rounds
having done nothing. It is gone.

## The fix (s59)

### 1. One pass; anarchy builds everything (`Core/Build/BuildVerdicts`, `Game/Build/BuildService.Verdicts.cs`)
`DoValidate` reads the game's verdicts **once** and decides with `BuildVerdicts.Decide` (pure, tested):

* **"Ignore collisions in my builds" ON (default)** — nothing is refused or failed for a collision or validation error
  (`OverlapExisting`, `InvalidShape`, `SteepSlope`, …): every planned net, object, decal, surface and area is applied, like the
  Anarchy mod (which disables these same error types, `ErrorType` 1/2/8/9/12/13/… "WithAnarchy"). Each kept piece is in the audit
  as *kept despite collisions*.
* Right before Apply (`NeutralizeVerdicts`, same frame as the Apply request): our temporaries lose `Warning` (would be **Deleted**),
  `Override` (would be **hidden**) and `Error`; pieces left out stay cancelled.
* **Existing buildings are never demolished, in every mode**: a building (or its sub-objects, or an existing road) the game marked
  with `Warning` loses it before Apply, so `ToolApplySystem` does not delete it. Our object/decal/area that touches an existing
  building is left out — just that piece, cancelled in place (`TempFlags.Cancel|Hidden`, the game's own mechanism, sub-objects and
  lanes included). A net touching a building is built anyway under anarchy (removing one edge would break the network); the
  building stays and the log names the net and its position.
* **Setting OFF (vanilla rules)** — flagged decorative pieces (and refused stall markings) are cancelled in place, once, with
  their reason in the audit; the build stops only when a **net** is refused or touches a building, and names it:
  `Placemaker build stopped by the game (InvalidShape): net 'Alley' at (612, -491)`.
* Not enough money always stops (not a collision).
* The ghost follows the setting: under anarchy it is non-optional and its red "refused" tint is cleared (`ClearGhostVerdicts`) —
  the preview shows exactly what the build will place.
* `AuditSurvivors`: under anarchy every planned piece the game hid after Apply (`Overridden`) is shown again unless it touches an
  existing building.

### 2. Removed
`MaxAutoExcludeAttempts`, `ExcludeErroneousItems` (2 m / 6 m / 12 m proximity probes), `Exclude`, `_dropFunctional`,
`_keptFunctional`, `_excluded`/`_excludeAttempts`, `ErrorHistogram`, `ClassifyOwnCollisions` (+ `_anarchyErrors`), the
`ProtectBuildings` exclude-and-retry, the ghost's `SelfOverlaps` optional rule. `Step.ResetForRetry` stays only for the
"duplicated temporaries" guard (one re-emission). Settings "Leave out parts that collide" / "Fix or skip rejected pieces" now only
matter with anarchy off (either one enables leaving out refused decorative pieces).

### 3. Plan-time collision awareness (quality, not a gate)
`ComposedPlan.ExistingNets` (set by `SiteSafety.Apply` from the site capture, captured city nets only) feeds `Declutter`: props,
trees and furniture are nudged (≤ 2 m) off or dropped from existing streets/sidewalks/paths with their full composition width, like
planned nets already were. Decals and parking pieces are never pushed. Existing props/trees are not captured; the build clears
those inside the outline in the same transaction (unchanged).

### Not done, and why
Giving our pieces a shared owner **at emit time** (sub-objects of the carrier) would make the game skip our-vs-our checks at the
source. It is not needed for "build everything" (Apply ignores `Error`), and it changes how the game generates, overrides and
applies every piece (non-Essential sub-objects get `Override` = hidden against city props; owner/sub-object buffers on the
carrier) — the s55/s58 post-Apply carrier already handles the hiding. Worth a separate, measured step if the red ghost/validation
work itself ever becomes a cost.
