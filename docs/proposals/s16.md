# s16 — roads say what they are: Automatic names its road, road roles, road legend, road mixes

User feedback: "the default street should be the two-lane road, the avenue the four-lane road… Automatic doesn't tell
you enough. What am I actually getting? What are these roads being drawn on my screen? I don't even know what a
roundabout road is." Lead follow-up: named "road mixes" with a visual per option, gallery renders of every mix.

## What Automatic places now (roads layer)

Vanilla 1.6.2f1 prefab names (catalog dump / `docs/ASSET-CURATION.md`), in `Core/Layers/Roads/RoadRoles.cs`:

| role | control | Automatic (first one the playset has wins) |
|---|---|---|
| Street | `streetAsset` | `Small Road` = **Two-Lane Road** (16 m) |
| Avenue | `avenueAsset` | `Medium Road` = **Four-Lane Road** (24 m) → `Medium Road Divided` → `Small Road` |
| Local (cul-de-sacs, side streets) | `localAsset` | the street pick, else `Small Road` |
| Roundabout ring | `roundaboutAsset` | `Small Road Oneway` = **Two-Lane One-Way Road** (2 lanes in the ring direction = the Four-Lane avenue's per-direction capacity) → 3-lane → 1-lane one-way |
| Perimeter (new control) | `perimeterAsset` | the street pick, else `Small Road` |
| Car-free street | `pathAsset` | pathway pool (Pavement Path), unchanged |

Before: every road role resolved to the `net.road` pool's first item, which is **"Pedestrian Street Small"** in the
current dump — automatic streets were pedestrian streets and avenues the same road as streets. Now the planner emits
`AssetRef("", <role picks>)`; `AutoAssets.Set` takes the first *loaded* fallback (and, new, the first fallback when
`Exists == null`, i.e. "everything exists" in pure tests). Planner block widths use the automatic prefab's real width.

## Contract changes (additive — lead, please review)

`Core/Contracts.cs`
- `ControlSchema.DescriptionKey` — one visible line under the label ("The ordinary streets between blocks.").
- `ControlOption.DetailKey` + `ControlOption.Swatch` (`List<OptionSwatch>`: role, colour, width m, green, bike) — option
  detail line and a generated picture.
- `PlannedNet/PlannedObject/PlannedSurface/PlannedArea.Control` — the asset control that chose the element's asset
  (roads tag every net). Copied by `PathJoins`.
- `ILinkedControls { OnValueSet(settings, id) → driven ids; Derive(settings) }` — a control that writes others (road mix)
  and is derived back from them. `DesignEditor.SetValue` calls both (driven ids are locked like the control);
  `ApplyPreset` derives; `UiModels.Step` derives a copy before sending values (old saves show the right mix).
- `IAutoAssetHints.AutoCandidates(controlId, settings)` — what Automatic *would* place for a control the current plan
  does not use.

`UI/src/contract.ts` + `Core/Tool/UiModels.cs`
- `Control.description?`, `ControlOptionView { detail?, swatch?: SwatchStripe[] }`.
- `StepView.resolvedAssets?: Record<controlId, { id, name?, icon?, unused? }>` — generic for every asset control:
  elements tagged with the control decide (most used prefab); layers that tag nothing fall back to the first element of
  the control's category; controls the plan does not use get the generator's `IAutoAssetHints` candidate with
  `unused: true`. Names/thumbnails come from the game catalog (`UiModels.Design(..., assetLabel)`; the UI system
  passes `AssetLabelOf(category, id)`), and the design is re-pushed when `AssetsResolvedStamp` changes.
- `StepView.netLegend?: { role, label, color, count, lengthM, assetId?, assetName?, control? }[]` — roads of the
  step's plan by role (only roles present; car-free paths only next to real roads).
- `normalizeStep` (UI/src/lib/bindings.ts) keeps both fields (it dropped unknown fields before).

## Road roles in plain words

Road-type controls are now Street / Local road / Avenue / Roundabout ring / Perimeter road / Car-free street, each with
a description line, and the tooltips state the automatic pick. **Unused roles**: master has no generic
"disabled with reason" yet (s15 is adding it), so they stay visible (current behaviour); instead the picker says
"Automatic · Four-Lane Road — not in this layout" (`resolvedAssets[...].unused`). When s15 lands, `unused` can drive
its disabled state ("Not used by this layout").

## Road mixes (`roadMix`, Essential, top of "Road types")

`Core/Layers/Roads/RoadMixes.cs`: Automatic (= standard), Quiet residential, Alleyway grid, Pedestrian core, Boulevards,
Downtown, Bike friendly, Country lanes, + Custom. A mix writes street/local/avenue/roundabout/perimeter picks and all
nine upgrade toggles; the value is derived (`RoadMixes.Match`), so picking a single road reads "Custom", old saves
load as Automatic or Custom, presets keep matching. The planner never reads `roadMix`. Only vanilla prefabs that are
in the fixture catalog (test). One-way pairs for Downtown were left out (needs generator support).

UI: options with a swatch/detail render as two-per-row cards: a tiny generated plan (avenue down the middle, two
streets across, a local stub) in role colours at relative widths, green edge = trees/verges, green core = bike lanes,
plus the detail line ("Streets: Two-Lane · Avenues: Four-Lane").

## Preview colours and legend

One palette (`RoadRoles.Color`): street `#f2f2f2`, avenue `#59d9ff`, local `#8fe07a`, roundabout ring `#c58cff`,
perimeter `#ffa64d`, car-free `#ffd173`. Used by the in-game overlay (`PlacemakerOverlaySystem.NetColor`), the
panel legend ("■ Street · Two-Lane Road · 1.2 km", `NetLegend` in Controls.tsx, shown at the top of the step), the
mock map and the gallery (role-coloured centre band + legend entries; per-card road legend; `roads` in gallery.json).
Gallery: `--only roads` renders `mix-<id>` for every mix (grid with an avenue column and row).
